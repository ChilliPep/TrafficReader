PART I — SINGLE ANSWER QUESTIONS (1–60)
01

What is defined as a collection of related data with implicit meaning?

DATABASE — A database is a collection of related data with an implicit meaning, representing some aspect of the real world (a "mini-world" or Universe of Discourse).
02

Which system suffers from data dependence where the file structure is defined in the program code?

TRADITIONAL FILE SYSTEM — In a file-based system, file structure and access logic are hard-coded into application programs, causing data dependence: any change to the file format requires modifying every program that uses it.
03

In the ANSI-SPARC architecture, which level describes how the data is actually stored on the disk?

INTERNAL LEVEL (Physical Level) — The internal/physical level deals with how data is physically stored on disk: file structures, indexes, storage allocation, and access paths.
04

Which property ensures that a change in the physical storage structure does not affect the conceptual schema?

PHYSICAL DATA INDEPENDENCE — Physical data independence means changes to the internal/physical level (e.g., switching storage format or index) do not require changes to the conceptual schema or user views.
05

Which component of a DBMS is responsible for ensuring the database remains in a consistent state during a crash?

RECOVERY MANAGER — The recovery manager (part of the transaction manager) uses logs and checkpoints to restore the database to a consistent state after a crash, undoing incomplete transactions and redoing committed ones.
06

What is the main advantage of a relational database over a hierarchical one?

FLEXIBILITY & NO REDUNDANCY — Relational databases allow flexible many-to-many relationships without data duplication; hierarchical models force tree structures that cannot represent M:N relationships without redundancy, and navigation is rigid (parent → child only).
07

In SQL, which command is used to add a new column to an existing table?

ALTER TABLE ... ADD COLUMN — Example: ALTER TABLE employees ADD COLUMN department VARCHAR(50); This is a DDL statement that modifies the table schema.
08

Which data type would you use for a column that stores long descriptions of products?

TEXT — The TEXT data type (or VARCHAR(MAX) in some systems) is used for variable-length strings of large or unknown size, ideal for long descriptions.
09

A "Weak Entity" in an ER diagram is identified by its relationship with what?

ITS OWNER (STRONG) ENTITY — A weak entity cannot be uniquely identified by its own attributes alone. It depends on a strong (owner) entity through an identifying relationship. Its partial key + the owner's primary key together form its full identifier.
10

What does the "I" in ACID properties stand for?

ISOLATION — Isolation means that concurrent transactions execute as if they were serial (one at a time). Intermediate states of a transaction are not visible to other transactions.
11

Which SQL operator is used to filter results based on a range of values?

BETWEEN — Example: WHERE salary BETWEEN 3000 AND 7000. It is inclusive of both boundary values. Equivalent to >= low AND <= high.
12

The process of "Normalization" is primarily used to achieve what?

ELIMINATION OF REDUNDANCY & UPDATE ANOMALIES — Normalization organizes data into relations that minimize redundancy and avoid insertion, deletion, and update anomalies by ensuring each fact is stored in exactly one place.
13

Which normal form deals with removing partial functional dependencies?

SECOND NORMAL FORM (2NF) — A table is in 2NF if it is in 1NF and every non-key attribute is fully functionally dependent on the entire primary key (no partial dependencies on a part of a composite key).
14

A "Foreign Key" must reference which column in another table?

PRIMARY KEY (or UNIQUE KEY) — A foreign key must reference a column (or set of columns) that is declared as a primary key or unique constraint in the referenced table, ensuring referential integrity.
15

What is the default sorting order of the ORDER BY clause in SQL?

ASCENDING (ASC) — By default, ORDER BY column sorts from the smallest to largest value. Use DESC keyword to reverse the order.
16

Which clause is used to filter rows AFTER an aggregate function has been applied?

HAVING — HAVING filters groups after GROUP BY and aggregation. Unlike WHERE (which filters individual rows before aggregation), HAVING works on aggregated results. Example: HAVING COUNT(*) > 5.
17

In the Relational Model, what is the cardinality of a relation?

NUMBER OF ROWS (TUPLES) — Cardinality = number of tuples in a relation. Degree = number of columns (attributes). These are distinct concepts: cardinality changes with data, degree changes with schema modifications.
18

Which SQL command is used to empty a table but keep its structure?

TRUNCATE TABLE — TRUNCATE removes all rows from a table but preserves the table definition, constraints, and indexes. It is faster than DELETE (no row-by-row logging) and cannot be rolled back in most DBMSs.
19

What type of relationship exists between a "Student" and a "Course"?

MANY-TO-MANY (M:N) — A student can enroll in many courses, and a course can have many students. This requires a junction/bridge table (e.g., Enrollment) with foreign keys to both tables.
20

Which symbol represents an attribute in an ER Diagram?

ELLIPSE (OVAL) — In standard ER notation: Entities = rectangles, Relationships = diamonds, Attributes = ellipses. Double ellipse = multi-valued attribute; dashed ellipse = derived attribute.
21

What is "Metadata"?

DATA ABOUT DATA — Metadata describes the structure, format, constraints, and meaning of the actual data. In a DBMS, the data dictionary (system catalog) stores metadata such as table names, column types, indexes, and access privileges.
22

Which SQL join returns all rows when there is a match in one of the tables?

FULL OUTER JOIN — FULL OUTER JOIN returns all rows from both tables: matched rows combined, unmatched rows from the left table with NULLs for the right columns, and unmatched rows from the right table with NULLs for the left columns.
23

The "Generalization" process in database design is which type of approach?

BOTTOM-UP APPROACH — Generalization starts from specific entities and abstracts common attributes into a higher-level (superclass) entity. It is bottom-up. The reverse, Specialization, is top-down (starting from a general entity and creating subclasses).
24

What is a "Composite Attribute"?

AN ATTRIBUTE MADE OF SUB-ATTRIBUTES — A composite attribute can be subdivided into smaller meaningful parts. Example: Full Name → First Name + Last Name; or Address → Street + City + Zip.
25

Which SQL keyword is used to return only different values?

DISTINCT — Example: SELECT DISTINCT department FROM employees; eliminates duplicate values from the result set. Can also be used inside aggregate functions: COUNT(DISTINCT column).
26

What is the purpose of the COMMIT command in SQL?

PERMANENTLY SAVES A TRANSACTION — COMMIT ends a transaction and makes all changes permanent in the database. Once committed, changes cannot be undone with ROLLBACK. It satisfies the Durability property of ACID.
27

In PostgreSQL, which tool is commonly used as a GUI to manage databases?

pgAdmin — pgAdmin is the most popular open-source graphical administration and development tool for PostgreSQL. It provides a browser-based interface for managing databases, running queries, viewing query plans, and monitoring server activity.
28

What is a "Recursive Relationship"?

A RELATIONSHIP OF AN ENTITY WITH ITSELF — A recursive (unary) relationship is when an entity participates in a relationship with itself. Example: an Employee entity with a "manages" relationship — one employee manages other employees of the same type.
29

Which operator is used to combine the results of two SELECT statements?

UNION — UNION combines result sets of two queries, removing duplicates. UNION ALL keeps duplicates (and is faster). Both queries must have the same number of columns with compatible data types.
30

A "Candidate key" that is not chosen as the Primary Key is called what?

ALTERNATE KEY — A candidate key is any attribute (or set of attributes) that uniquely identifies tuples. If multiple candidates exist, one is chosen as the primary key; the remaining candidates are called alternate keys.
31

Which integrity rule states that "No part of a primary key can be null"?

ENTITY INTEGRITY RULE — The entity integrity constraint mandates that no attribute forming part of the primary key may hold a NULL value, since the primary key must uniquely and completely identify every tuple.
32

What does the "Degree" of a relationship represent?

NUMBER OF ENTITIES PARTICIPATING IN THE RELATIONSHIP — Degree = number of entity types involved: Unary (degree 1, recursive), Binary (degree 2, most common), Ternary (degree 3), etc. Not to be confused with degree of a relation = number of attributes.
33

Which SQL function returns the average value of a numeric column?

AVG() — Example: SELECT AVG(salary) FROM employees;. AVG ignores NULL values. It is an aggregate function used with or without GROUP BY.
34

What is a "Derived Attribute"?

AN ATTRIBUTE COMPUTED FROM OTHER DATA — A derived attribute is not physically stored; its value is calculated at query time from other attributes. Example: Age derived from DateOfBirth; Total derived from Price × Quantity. Shown as a dashed ellipse in ER diagrams.
35

Which SQL command is used to change data inside a table?

UPDATE — Example: UPDATE employees SET salary = 5000 WHERE id = 10;. Always use a WHERE clause to avoid updating all rows accidentally. UPDATE is a DML statement.
36

What is the main characteristic of a "Shared-Nothing" architecture?

EACH NODE HAS ITS OWN PRIVATE MEMORY AND DISK — In shared-nothing architecture, nodes do not share RAM or storage. Each processes its own data partition independently. This enables high scalability and fault isolation, used in systems like distributed databases and MPP engines.
37

In a 1:M relationship, where is the Foreign Key usually placed?

ON THE "MANY" SIDE — In a one-to-many relationship, the foreign key is placed in the table on the "many" side, referencing the primary key of the "one" side. Example: Orders table has a customer_id FK pointing to Customers.
38

Which level of the ANSI-SPARC model provides "Views" for different users?

EXTERNAL LEVEL (View Level) — The external level consists of multiple user views, each showing only the portion of the database relevant to that user or application, hiding the rest and providing data independence and security.
39

What is the standard port for PostgreSQL?

PORT 5432 — PostgreSQL listens on TCP port 5432 by default. This is the IANA-registered port for PostgreSQL. It can be changed in postgresql.conf.
40

Which constraint ensures that all values in a column are different?

UNIQUE CONSTRAINT — The UNIQUE constraint prevents duplicate values in a column (or combination of columns). Unlike a primary key, a unique column can contain NULL values (in most DBMSs, NULLs are treated as distinct).
41

What is "Referential Integrity"?

EVERY FOREIGN KEY VALUE MUST MATCH AN EXISTING PRIMARY KEY — Referential integrity ensures that a foreign key value either matches a primary key in the referenced table or is NULL. It prevents orphan records and is enforced by the DBMS via ON DELETE/ON UPDATE actions.
42

Which command is used to revoke permissions from a user?

REVOKE — Example: REVOKE SELECT ON employees FROM username;. It is a DCL (Data Control Language) statement, the opposite of GRANT. Revoked privileges no longer allow the user to perform the specified operations.
43

In ER modeling, what is "Aggregation"?

TREATING A RELATIONSHIP AS AN ENTITY — Aggregation is an abstraction in which a relationship (and the entities it connects) is treated as a higher-level entity that can itself participate in another relationship. Used when a relationship needs to have a relationship with a third entity.
44

What does the % wildcard represent in the LIKE operator?

ANY SEQUENCE OF ZERO OR MORE CHARACTERS — In SQL's LIKE pattern matching: % matches any string of any length (including empty). Example: WHERE name LIKE 'A%' finds names starting with "A". The _ wildcard matches exactly one character.
45

Which part of the DBMS handles the parsing of SQL statements?

QUERY PROCESSOR / DDL & DML COMPILER — The query processor (including the parser and query optimizer) receives SQL statements, checks syntax, validates against the catalog metadata, and compiles/optimizes them into an execution plan before passing to the storage engine.
46

What are the two main advantages of using a DBMS over a traditional file system?

1. DATA INDEPENDENCE — Schema changes don't require rewriting application code.

2. REDUCED REDUNDANCY & CONCURRENT ACCESS / SECURITY — Central control eliminates duplication, enforces integrity, supports multi-user concurrency, and provides access control and recovery mechanisms.
47

Which two SQL commands belong to DDL (Data Definition Language)?

CREATE and DROP (also ALTER, TRUNCATE) — DDL commands define and modify the database schema (structure). DML commands (SELECT, INSERT, UPDATE, DELETE) manipulate data within that structure.
48

Which two symbols are used to represent multi-valued and simple attributes in an ER Diagram?

DOUBLE ELLIPSE = multi-valued attribute (can hold multiple values, e.g., phone numbers).
SINGLE ELLIPSE = simple (single-valued) attribute. Additional: dashed ellipse = derived; composite = ellipse connected to sub-ellipses.
49

Name two aggregate functions that can be used with the GROUP BY clause.

COUNT() — counts rows in each group.
SUM() — totals a numeric column per group.
Others: AVG(), MAX(), MIN(). All aggregate functions collapse multiple rows into a single summary value per group.
50

Identify the two types of data independence in the three-level architecture.

1. PHYSICAL DATA INDEPENDENCE — Ability to change the internal/physical schema without changing the conceptual schema.

2. LOGICAL DATA INDEPENDENCE — Ability to change the conceptual schema without changing external views or application programs.
51

Select two types of OUTER JOINs used in SQL.

LEFT OUTER JOIN — Returns all rows from the left table, NULLs for unmatched right rows.
RIGHT OUTER JOIN — Returns all rows from the right table, NULLs for unmatched left rows.
(Third type: FULL OUTER JOIN — all rows from both tables.)
52

Identify two essential properties of a Primary Key.

1. UNIQUENESS — Each value must uniquely identify exactly one tuple in the relation; no two rows can share the same primary key value.

2. NON-NULLABILITY — No attribute forming part of the primary key may be NULL (Entity Integrity Rule).
53

Which two components are part of the DBMS Storage Manager?

1. BUFFER MANAGER — Manages the in-memory buffer pool; brings pages from disk into RAM and decides which pages to evict (replacement policy).

2. FILE MANAGER — Manages disk space allocation, file organization, and interaction with the OS file system.
54

Name two types of keys found in a relational schema (excluding Primary Key).

FOREIGN KEY — An attribute referencing the primary key of another relation, enforcing referential integrity.
CANDIDATE KEY — Any minimal set of attributes that uniquely identifies tuples; the primary key is chosen from these. Alternate keys are the unchosen candidates.
55

Which two constraints ensure data quality at the column level?

NOT NULL — Ensures a column cannot contain NULL values.
CHECK — Validates that column values satisfy a specified condition. Example: CHECK (age >= 0 AND age <= 120). Both enforce domain integrity at the column level.
56

Identify two historical data models used before the Relational Model.

1. HIERARCHICAL MODEL — Organizes data in a tree structure (parent–child). Used in IBM IMS. Cannot handle M:N relationships without redundancy.

2. NETWORK MODEL — Uses a graph (pointers/links) to represent many-to-many relationships. Defined by the CODASYL standard (e.g., IDMS).
57

Which two SQL clauses are essential for sorting and limiting records?

ORDER BY — Sorts the result set by one or more columns (ASC or DESC).
LIMIT (or FETCH FIRST n ROWS ONLY in standard SQL, or TOP in SQL Server) — Restricts the number of rows returned. Together they are used for pagination.
58

Identify two aspects of "Specialization" in EER modeling.

1. DISJOINT vs. OVERLAPPING — Disjoint: a subclass entity can belong to only one subclass. Overlapping: an entity can belong to multiple subclasses simultaneously.

2. TOTAL vs. PARTIAL — Total: every superclass entity must belong to at least one subclass. Partial: superclass entities may not belong to any subclass.
59

Name two keywords used to define table relationships in a CREATE TABLE statement.

FOREIGN KEY — Declares a referencing column.
REFERENCES — Specifies the referenced table and column.
Example: FOREIGN KEY (dept_id) REFERENCES Department(id). Together they establish referential integrity between tables.
60

In the query SELECT department, COUNT(*) FROM Employees WHERE salary > 5000 GROUP BY department HAVING COUNT(*) > 2, what are the two main logical outcomes?

1. FILTERING BEFORE GROUPING — The WHERE salary > 5000 clause filters individual rows first, so only employees earning more than 5000 are included in the grouping.

2. FILTERING AFTER GROUPING — The HAVING COUNT(*) > 2 clause then filters out departments that have 2 or fewer qualifying employees, returning only departments with more than 2 high earners.
PART II — MULTIPLE ANSWER QUESTIONS (61–75)
61

What are the three main components (levels) of the ANSI-SPARC architecture?

1. EXTERNAL LEVEL — Individual user views; what each user or application "sees."
2. CONCEPTUAL LEVEL — The community/logical view; describes what data is stored and the relationships among entities (the full schema).
3. INTERNAL LEVEL — The physical storage level; how data is physically stored on disk (files, indexes, etc.).
62

Identify three fundamental parts of an Entity-Relationship (ER) model.

1. ENTITIES — Real-world objects or concepts with independent existence (represented as rectangles).
2. ATTRIBUTES — Properties that describe entities (represented as ellipses).
3. RELATIONSHIPS — Associations between entities (represented as diamonds), with cardinality and participation constraints.
63

Which three operations are considered DML (Data Manipulation Language)?

1. INSERT — Adds new rows to a table.
2. UPDATE — Modifies existing rows.
3. DELETE — Removes rows from a table.
(Note: SELECT is sometimes classified as DML or as its own DQL category depending on the textbook.)
64

Choose three types of attributes (Simple, Composite, etc.) in an ER Diagram.

1. SIMPLE (ATOMIC) — Cannot be divided further (e.g., SSN, Age).
2. COMPOSITE — Divisible into sub-parts (e.g., Address → Street, City, Zip).
3. MULTI-VALUED — Can hold multiple values for one entity (e.g., phone numbers). Also notable: Derived attributes (computed from others).
65

Which three SQL keywords are used together in a basic data retrieval query?

1. SELECT — Specifies which columns to retrieve.
2. FROM — Specifies the table(s) to query.
3. WHERE — Filters rows based on a condition.
Together: SELECT column FROM table WHERE condition; — the foundational SQL query structure.
66

Identify three integrity constraints used in a relational database.

1. DOMAIN CONSTRAINT — Each attribute value must come from its defined domain (data type, range).
2. ENTITY INTEGRITY — No primary key attribute can be NULL.
3. REFERENTIAL INTEGRITY — Every foreign key value must match an existing primary key in the referenced table, or be NULL.
67

Which three data types are standard in most SQL implementations?

1. INTEGER (INT) — Whole numbers without decimal points.
2. VARCHAR(n) — Variable-length character strings up to n characters.
3. DATE — Calendar date (year, month, day).
Also common: FLOAT, DECIMAL, BOOLEAN, TEXT, TIMESTAMP.
68

Select the three types of binary relationships between entities (1:1, etc.).

1. ONE-TO-ONE (1:1) — Each entity in A relates to at most one entity in B, and vice versa. Example: Person ↔ Passport.
2. ONE-TO-MANY (1:M) — One entity in A relates to many in B. Example: Department → Employees.
3. MANY-TO-MANY (M:N) — Many entities in A relate to many in B. Example: Students ↔ Courses.
69

Identify three benefits provided by the Three-Level Architecture.

1. DATA INDEPENDENCE — Changes at one level don't affect other levels (physical and logical independence).
2. SECURITY & PRIVACY — Users only see the external view they're authorized for; sensitive data can be hidden.
3. CUSTOMIZED USER VIEWS — Different users or applications can have tailored views without each needing access to the full schema.
70

Which three aggregate functions are most commonly used to summarize data?

1. COUNT() — Counts the number of rows (or non-NULL values).
2. SUM() — Totals all numeric values in a column.
3. AVG() — Computes the arithmetic mean of a numeric column.
Also widely used: MAX() and MIN().
71

Select three modern database architectures (Distributed, Federated, etc.).

1. DISTRIBUTED DATABASE — Data is stored across multiple physically separate nodes/sites, coordinated to appear as one logical database.
2. FEDERATED DATABASE — Multiple autonomous databases integrated under a single interface without a central store; each retains its own control.
3. CLOUD DATABASE — Hosted and managed on cloud infrastructure (DBaaS), offering elastic scaling, high availability, and pay-per-use pricing.
72

Identify three key steps in creating a relational schema from an ER diagram.

1. MAP STRONG ENTITIES — Each strong entity type becomes a table; its simple attributes become columns; the primary key attribute becomes the PK.
2. MAP RELATIONSHIPS — 1:M relationships are implemented by placing the FK on the "many" side; M:N relationships become a new junction table with FKs to both entities.
3. MAP WEAK ENTITIES — Weak entity becomes a table; its PK = partial key + FK to the owner entity's PK.
73

Identify three specific characteristics of a "Relation" in the relational model.

1. NO DUPLICATE TUPLES — Every row in a relation must be unique (enforced by the primary key).
2. ATTRIBUTE VALUES ARE ATOMIC — Each cell holds a single, indivisible value (First Normal Form).
3. ORDER OF TUPLES / ATTRIBUTES IS IRRELEVANT — The logical order of rows and columns does not matter; columns are identified by name, not position.
74

Which three concepts (Weak Entities, Generalization, etc.) are part of "Advanced ER Modeling"?

1. WEAK ENTITIES — Entities that cannot be uniquely identified without their owner entity; use identifying relationships and partial keys.
2. GENERALIZATION / SPECIALIZATION — Superclass–subclass hierarchies; EER diagrams extend basic ER to model inheritance.
3. AGGREGATION — Treating a relationship (and its participating entities) as a higher-level entity that can itself participate in further relationships.
75

Analyze the result of a LEFT JOIN between a 'Customers' table (5 rows) and 'Orders' table (10 rows) where one customer has no orders. Identify three true statements about the output.

1. THE RESULT CONTAINS AT LEAST 5 ROWS — A LEFT JOIN guarantees all rows from the left table (Customers) appear in the result, regardless of whether a match exists in Orders.
2. THE UNMATCHED CUSTOMER ROW APPEARS WITH NULLs — The customer with no orders will still appear in the output, but all columns from the Orders table will be NULL for that row.
3. MATCHED ORDERS INCREASE THE ROW COUNT BEYOND 5 — If some customers have multiple orders, those customers appear multiple times (once per order), so the total result can be more than 5 rows (up to 10 + 1 = 11 if one customer has no orders and others account for all 10 orders).
